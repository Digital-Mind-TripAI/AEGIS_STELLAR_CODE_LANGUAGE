# Stellar Windows x64 v0.1 Native Build Boundary

## Tranche 4 outcome

`stellar build` accepts a package-root `stellar.package/v0.1` manifest, an explicit new output directory, and the versioned core standard-library root. It first repeats package, module, dependency-lock, RELIC-interface, target, profile, ABI, type, effect, and source-integrity checks. It then lowers build-eligible typed source through the compiler's existing AST/HIR/MIR authority into generated MASM; source can never provide assembly, paths, tool flags, entry points, or linker arguments.

Each module is assembled twice with fixed MSVC/MASM flags. Defined symbols, undefined symbols, relocations, and normalized disassembly must exactly match the compiler plan. A fixed `/NOENTRY /NODEFAULTLIB` PE32+ DLL is linked solely as an inspection image, twice, and its headers, exports, imports, and disassembly are inspected. The compiler never loads or executes that image, exposes no `run` command, and records `loaded: false`, `ran: false`, and `executionEnabled: false`.

The reviewed Tranche 4 native ABI supports `bool`, `i32`, `i64`, `u32`, `u64`, and `f64`, explicit checked conversions, checked and wrapping integer arithmetic, layout-aware locals/assignment, named nonrecursive calls, `if/else`, compiler-proven bounded loops with scoped `break`/`continue`, and caller-owned `Result` output with integer status. Floating-point arguments occupy `XMM0` through `XMM3` by argument ordinal; integral and pointer arguments occupy the corresponding Windows x64 general-purpose argument register, and later arguments use the fixed outgoing stack area. Every `Result<T, Code>` call uses an integer status in `EAX` and a caller-owned hidden output pointer. This is the versioned `stellar-win64-v0.1` convention declared as `win64-ordinal-expanded/v1` plus `eax-status+caller-out-pointer/v1` by the compiler trace and every pure RELIC interface. Aggregate parameters are borrowed through compiler-generated pointers and aggregate results are copied into that output. Each call trace binds caller, callee symbol, ABI positions, output-pointer ordinal, result type, result size, and source span; there is no fallback ABI.

Structs and fixed arrays have compiler-computed size, alignment, field offsets, and element stride. They live inline in bounded stack slots, support field/index access and assignment, and are copied with compile-time-known byte counts. Array fill evaluates its value once and performs a bounded sequence of typed copies. Bounded slices use the caller-owned descriptor `{ptr, len}`. Every slice parameter rejects a null data pointer at function entry (`-16`) and rejects a length above its declared bound (`-17`); a literal index then checks the accepted runtime length and returns `-17` when unavailable. Failed numeric conversions return `-15`. The language continues to expose neither heap allocation nor garbage collection, arbitrary raw pointer construction, recursion, or effects.

The fixed semantic conformance runner is test-only. It links and executes only the hash-observed generated objects for the reviewed f64, struct, array, and slice fixtures plus the authoritative pure RELIC object needed by the slice fixture. It is not reachable from the Stellar CLI or application, accepts no Stellar source or package argument, and does not open S7001 or provide arbitrary native execution.

## Integrity and capability boundary

The canonical build lock binds package and dependency integrity, emitted assembly, module symbol/relocation/disassembly evidence, exact standard-library lock, fixed toolchain, target/profile/ABI, and linked-image evidence. Raw COFF and PE hashes are recorded as reproducible only when byte identity is actually observed; normalized evidence must always reproduce. Inputs are rechecked after linking, failed output trees are removed, and existing output paths are never overwritten.

All manifest capabilities remain refused. Only hash-exact, capability-free core RELIC interfaces may link, and the standard-library verifier keeps ConsoleWrite unauthorized, uncompiled, and disabled. Checksum integrity is not authorization. No arbitrary user-defined native execution or capability use can be enabled until authenticated Custodian/Steward-issued Relation Contracts and independently verified OS-enforced process isolation pass the mandatory gate.

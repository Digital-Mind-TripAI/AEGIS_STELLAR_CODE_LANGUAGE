# Stellar Windows x64 v0.1 — T7e fixed target-host discovery

Status: **OFFLINE BUILT; UNSIGNED REVIEW INPUT; TARGET DISCOVERY NOT RUN; S7001 CLOSED**.

`stellar-target-host-discovery.exe` is a fixed-scope native Windows x64 observer. It requests no elevation, accepts no package path, executes no package artifact, links no scripting or Node runtime, opens no network endpoint, and exposes no Apply operation. Its accepted forms are `--self-test` and `--output target-host-discovery.canonical.json`. The Known Folder result must equal the pinned `C:\ProgramData` root. Every ancestor through `C:\ProgramData\AEGIS\Stellar\v0.1\evidence` is opened without delete sharing, retained through output, identified, and rejected if it is a reparse point. The evidence directory must have a SYSTEM, BUILTIN Administrators, or explicitly approved launch/service SID owner and a non-null valid DACL. The shared production ACL function maps generic rights and rejects every direct, inherited, or object allow ACE granting write data/append, extended attributes, attributes, delete/delete-child, DACL, or owner authority to any SID outside that exact allowlist. Deny ACEs do not create authority; malformed and unsupported ACEs fail closed. Missing directories and alternate, reserved, trailing-dot/space, path, ADS, or traversal names are refused.

The accepted canonical D4 plan artifact (`sha256:437e6d…b3a8`, internal plan hash `sha256:9958eb…a3b0`) is embedded as native read-only data only after the builder verifies both hashes, all 91 resource IDs, and all 77 file destinations. Runtime observations are keyed by those exact resource IDs. The generated Draft 2020-12 schema names all 91 properties and closes every known/unavailable shape by resource kind. Before semantic validation, the external output validator verifies both JSON documents against the exact discovery and receipt schemas whose authority hashes are compiled into the validator. It then independently enforces exact correspondence, kind, cardinality, plan bindings, stable double-read equality, and receipt-to-evidence binding.

The compiled scope reads the process token/elevation/SID/privileges; exact Custodian and Broker SCM configuration/status/security; every planned file plus protected roots with owner/DACL, volume/file identity, hash, streams, reparse attributes, and hardlink count; fixed registry values; certificate entries/policy; fixed firewall rule values; and host/install identity. For each exact CNG name (`AegisStellarCustodian-Issuer-P256-v1` and `AegisStellarExecutionBroker-Attestation-P256-v1`), both the Platform and Software KSP are queried with `NCRYPT_MACHINE_KEY_FLAG`. Platform is the fixed configured authority for this release; at most one provider is accepted, while both provider observations/errors, public kid, export policy, and key security remain visible. Missing configured-Platform evidence closes the resource as unavailable instead of selecting Software by inference.

The observer performs the complete read twice. Exact canonical snapshot digests must match before output creation. It reports `stableDoubleRead` and `noTargetMutationObserved`; it does not claim that output creation is zero mutation. Evidence and the separate `target-host-discovery.operator-receipt.canonical.json` are create-new and flush-verified. The receipt binds the intended zero exit code, flush result, exact fixed path, root-policy decision, output byte length, SHA-256, volume serial, and file ID. `validate-t7e-output.ts` verifies the evidence semantics and receipt binding outside the native observer.

The separately built hostile native harness operates only in a unique unelevated temporary root. Acceptance requires actual OS fixtures for a reparse ancestor, hardlink, ADS, sparse file over 64 MiB, output collision, ACL denial, and injected writer/flush failure. It invokes the same production ACL function against actual temp-directory security and exact synthetic native descriptors covering Authenticated Users, BUILTIN Users, the local launch SID, generic write/all, inherited/object ACEs, delete-child, write-EA, write-DACL, write-owner, deny semantics, and the exact allowed identities. If the OS refuses creation of a required fixture, the harness fails acceptance rather than reporting a skip. Target-host execution remains a separately authorized gate.

Static imports include documented C/C++ runtime imports and Windows Known Folder support such as `LoadLibraryExW`, `GetProcAddress`, and `SHELL32.dll`. Those dynamic-loader imports are not described as impossible; source, argument, and native-import inspection establish that no package PE execution or arbitrary dynamic-load path is exposed.
